# launcher-shortcut Specification

## Purpose

Быстрый доступ к созданию новой записи через меню долгого нажатия на иконку приложения: статический шорткат лаунчера открывает экран создания записи из любого состояния приложения, с корректным back stack, без дублирования уже открытого экрана и без потери шортката при смене иконки. Capability также фиксирует гарантию launch-семантики: при работающем приложении обычный повторный запуск возвращает пользователя на текущий экран с сохранением состояния.

## Requirements

### Requirement: Статический шорткат «Добавить запись» объявлен для лаунчера

Приложение SHALL объявлять статический шорткат с идентификатором `add_item`, подписью из строкового ресурса `add_item` и иконкой «плюс». Выбор шортката в лаунчере MUST доставлять в приложение intent с action `com.dayscounter.action.CREATE_ITEM`.

#### Scenario: Пункт в меню долгого нажатия

- **WHEN** пользователь долго нажимает на иконку приложения в лаунчере
- **THEN** в меню есть пункт «Добавить запись» с иконкой «плюс»

#### Scenario: Действие шортката

- **WHEN** пользователь выбирает пункт «Добавить запись»
- **THEN** приложение получает запуск с intent, action которого равен `com.dayscounter.action.CREATE_ITEM`

### Requirement: Шорткат доступен при любой иконке приложения

Шорткат MUST оставаться доступным для каждой из шести launcher-иконок приложения: смена иконки через настройки оформления SHALL не приводить к исчезновению пункта «Добавить запись».

#### Scenario: Шорткат после смены иконки

- **WHEN** пользователь меняет иконку приложения на любую другую и после этого долго нажимает на новую иконку
- **THEN** в меню есть пункт «Добавить запись», и он открывает экран создания записи

### Requirement: Шорткат при холодном старте открывает экран создания записи

Если приложение не запущено, выбор шортката MUST открыть экран создания записи поверх главного экрана, как при нажатии FAB. Кнопка «назад» с экрана создания MUST возвращать на главный экран.

#### Scenario: Холодный старт по шорткату

- **WHEN** приложение не запущено, и пользователь выбирает шорткат
- **THEN** открывается экран создания новой записи, и back stack содержит главный экран под ним

#### Scenario: Назад с экрана создания

- **WHEN** приложение открыто по шорткату, и пользователь нажимает «назад» на экране создания
- **THEN** отображается главный экран приложения

### Requirement: Шорткат при запущенном приложении открывает экран создания записи

Если приложение запущено на экране, отличном от экрана создания записи, и экран создания записи отсутствует в back stack, выбор шортката MUST открыть чистую форму создания записи поверх текущего стека.

#### Scenario: Запуск с произвольного экрана

- **WHEN** приложение открыто не на экране создания, экран создания записи отсутствует в back stack, и пользователь выбирает шорткат
- **THEN** поверх текущего экрана открывается чистая форма создания записи

#### Scenario: Экран редактирования открыт

- **WHEN** открыт экран редактирования существующей записи, и пользователь выбирает шорткат
- **THEN** поверх открывается чистая форма создания новой записи; «назад» возвращает к экрану редактирования

### Requirement: Повторный шорткат не дублирует экран создания записи

Если экран создания записи уже присутствует в back stack (наверху или под другим экраном), доставка intent шортката MUST NOT открывать второй экземпляр этого экрана: открытая форма с несохранённым вводом остаётся без изменений.

#### Scenario: Форма создания уже открыта

- **WHEN** экран создания записи открыт, и intent шортката доставляется повторно
- **THEN** второй экран создания не открывается, введённый текст и выбранные поля остаются как были

#### Scenario: Форма создания в середине стека

- **WHEN** экран создания записи открыт и над ним открыт другой экран приложения, и intent шортката доставляется повторно
- **THEN** навигация не выполняется, второй экземпляр экрана создания не появляется

### Requirement: Пересоздание Activity не открывает форму самовольно

Intent шортката MUST обрабатываться один раз на доставку: пересоздание Activity (поворот экрана, смена темы) SHALL не повторно открывать экран создания записи, если форма не была открыта или уже была закрыта пользователем.

#### Scenario: Поворот после закрытия формы

- **WHEN** приложение открыто по шорткату, пользователь закрыл форму создания, и затем Activity пересоздаётся (например, поворот экрана)
- **THEN** экран создания записи самовольно не открывается

### Requirement: Обычный запуск не пересоздаёт работающее приложение

Повторный запуск приложения с домашнего экрана при работающем приложении MUST возвращать пользователя на текущий экран с сохранённым состоянием.

#### Scenario: Тап по иконке при запущенном приложении

- **WHEN** приложение открыто на любом экране, и пользователь тапает по иконке приложения на домашнем экране
- **THEN** отображается текущий экран с сохранённым состоянием, приложение не перезапускается

### Requirement: Открытие по шорткату логируется в аналитику

Открытие экрана создания записи через шорткат MUST логироваться тем же событием действия пользователя, что и открытие по FAB, без добавления новых типов событий.

#### Scenario: События аналитики при запуске по шорткату

- **WHEN** пользователь открывает приложение по шорткату, и экран создания записи открывается
- **THEN** фиксируются то же событие действия «создание записи», что и при нажатии FAB, и стандартное событие просмотра экрана создания
