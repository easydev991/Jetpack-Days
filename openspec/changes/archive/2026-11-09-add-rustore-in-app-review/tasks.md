- [x] 8.4 Зафиксировать опыт тестирования SDK на эмуляторе (для будущих прогонов после публикации сборки):

  **Требование подписи (главное):** сервер RuStore сравнивает хэш подписи УСТАНОВЛЕННОГО APK с подписями `packageName` в своей базе — не совпали → generic `RuStoreException` «Application is not verified yet» / «Application signature not correct» на `requestReviewFlow`. Официально: <https://www.rustore.ru/help/guides/check-sign> и FAQ <https://www.rustore.ru/help/sdk/payments/kotlin-java/faq> («тестируемая разработчиком APK не совпадает с APK, загруженной в RuStore Консоль» — тестировать неопубликованную сборку МОЖНО, если подпись совпадает с консольной; версия в проверке не участвует). Практика: debug-подпись даёт эту ошибку; тестировать release-сборкой (`make apk FLAVOR=rustore`).

  **Среда:** ARM64-образ AVD (APK RuStore содержит только arm64-v8a/armeabi-v7a — x86_64 не подходит); официальный APK: <https://www.rustore.ru/download> → `static.rustore.ru/release/RuStore.apk`, ставить через `adb install` (страница в Chrome эмулятора сама отдаёт APK, ~55 МБ, в `/sdcard/Download/`; `adb install` принимает host-путь — девайсовый `/sdcard/...` даёт `failed to stat`, сначала `adb pull`); авторизация VK ID — вручную в окне эмулятора (Моё → Профиль → Войти). Перезапуск эмулятора может стереть данные AVD (RuStore, логин, приложение — переустанавливать).

  **Урок по дедлоку (исправлено в коде, см. 4.1):** `Task.await()` SDK — блокирующий `CountDownLatch`, доставка результата через main-looper; await на main-диспетчере = дедлок + ANR. Фикс: `withContext(Dispatchers.IO)` в `RuStoreReviewFlowLauncher.launch()`. Юнит-фейки этот класс багов не ловят — только живой SDK на эмуляторе.

  **Матрица сценариев** (все пройдены): milestone 1 → форма (фокус `ru.vk.store/...AddAppReviewActivity`) → BACK → `исход=Shown`; 5 записей в одной сессии → второй запрос не запускается (лимит сессии); рестарт → 6-я запись → milestone 5 → `RequestLimitReached` (вторая форма за день не показывается); без RuStore → тихий `NotInstalled`; счётчики проверять по файлу `files/datastore/review_counters.preferences_pb` (debug-сборка, `run-as`; protobuf: created_items_count/passed_milestones/pending_milestone).

  **Gotcha первой попытки (не откатывать код; опыт Jetpack-MyWorkouts):** сразу после свежей установки APK / входа в RuStore первый авто-запрос может упасть тихо — счётчики без passed/pending, в logcat следов нет; это не дефект лаунчера — повтор в новой сессии приложения проходит (`SHOWN`).

  **Наблюдение исходов на release-сборке (опыт Jetpack-MyWorkouts):** аналитика в release не пишет событие в logcat — `adb shell setprop log.tag.FA VERBOSE` и `adb shell setprop log.tag.FA-SVC VERBOSE`, тогда FA-SVC печатает `Logging event: ... name=review_auto_request, params=Bundle[{outcome=..., error_type=...}]`; так пойманы живьём SHOWN и REQUEST_LIMIT_REACHED.

  **Кросс-сессионный pending без новых записей (опыт Jetpack-MyWorkouts):** pending ставится при сохранении записи → в окне ~0,8 с до показа `am force-stop com.dayscounter` → рестарт: pending пережил kill, авто-запрос показывается при возврате на экран списка без создания новых записей; улика — `xxd` файла `files/datastore/review_counters.preferences_pb` (нужен `adb root`, `run-as` работает только на debug-сборке).

  **Автоматизация** (AVD 1260×2240): создание записи — FAB (1128,1796) → поле названия (630,400) → текст → иконка календаря (1139,1042) → «сегодня» (198,1300) → «Ok» (1061,1845) → «Сохранить» (630,2048); форма оценки закрывается ТОЛЬКО BACK (тап по uiautomator-узлу «Закрыть» не срабатывает). Для ad-hoc прогонов удобен mobile-mcp (элементные ссылки вместо координат) — включён глобально в zcode-конфиге.

  **Кнопка «Оценить приложение»**: с установленным RuStore `ACTION_VIEW` на текущий `APP_RATE_URL` (суффикс `/reviews`) перехватывается app links магазина и маршрутизируется в КАТАЛОГ (суффикс недокументирован); документированный URL без суффикса открывает страницу приложения (отзывы — вкладка на ней). Без RuStore — браузер. Кандидат на правку `APP_RATE_URL` — решение владельца (кнопка заморожена).

  **Открыто после публикации этой сборки в RuStore:** реальный submit отзыва (ветка `RuStoreReviewExists`), бан-ветки (`RuStoreApplicationBannedException`/`RuStoreUserBannedException`).
