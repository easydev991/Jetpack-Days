# Proposal

## Why

На rustore-сборке единственный способ попросить пользователя оценить приложение — ручная кнопка «Оценить приложение», которая просто открывает страницу отзывов в браузере. Это даёт худшую конверсию: пользователь должен самостоятельно добраться до формы оценки. RuStore In-App Review SDK позволяет показать нативную форму оценки и отзыва (шкала 1–5, отзыв опционален) прямо внутри приложения, а автоматические триггеры — запросить оценку в подходящий момент, не дожидаясь ручного действия.

## What Changes

- Подключение RuStore In-App Review SDK (артефакт `ru.rustore.sdk:review`, версия 10.5.2) ТОЛЬКО для rustore flavor: репозиторий `https://nexus-external.rustore.ru/repository/maven-rustore-exposed` с content-filter по группе `ru.rustore.sdk`, зависимость через `rustoreImplementation`. Это первая flavor-зависимость и первые flavor source-sets (`app/src/rustore/`, `app/src/github/`) в проекте.
- Кнопка «Оценить приложение» остаётся без изменений (отображение и поведение — как сейчас: браузерная ссылка `APP_RATE_URL`); SDK кнопкой не вызывается — это снимает конфликт с рекомендацией доков SDK не использовать кнопку «Оценить приложение» как триггер.
- Автоматический запрос оценки по milestone-порогам кумулятивного числа созданных записей `[1, 5, 15]` (редактирование записи счётчик не увеличивает): каждый milestone — один раз за жизнь установки (до полного удаления данных пользователем), не более одного авто-запроса за сессию, показ отложен до возврата на главный экран (~0.8 с), любая ошибка SDK в авто-режиме обрабатывается тихо.
- Персистентное хранилище счётчиков триггеров (DataStore): счётчик созданных записей, пройденные milestones, pending-состояние; сброс при полном удалении данных пользователем.
- Новое аналитическое событие авто-запроса review-флоу: исход (показ формы / ошибка с типом).
- Документация: AGENTS.md — RuStore Review SDK как второе разрешённое исключение офлайн-правила (сеть — внутри приложения RuStore, свой сетевой стек в приложение не добавляется); docs/deployment.md — новый maven-репозиторий для rustore-сборок.
- github flavor: поведение не меняется — кнопки оценки нет, SDK не подключается.

## Capabilities

### New Capabilities

- `app-review`: автоматический запрос оценки приложения на rustore-сборке — milestone-триггеры по числу созданных записей, показ нативной формы RuStore In-App Review SDK, персистентность и сброс счётчиков, flavor-гейтинг.

## Impact

- **Gradle**: `app/build.gradle.kts` (репозиторий с content-filter, `rustoreImplementation`, первые flavor source-sets), `gradle/libs.versions.toml` (версия SDK).
- **Новые файлы**: домен (интерфейс лаунчера review-флоу без android-типов, use case milestone-логики), data (хранилище счётчиков по образцу `AppSettingsDataStore`), flavor-реализации (`app/src/rustore/` — SDK-лаунчер; `app/src/github/` — no-op).
- **Изменённые файлы**: `ui/viewmodel/CreateEditScreenViewModel.kt` (хук счётчика на успешное создание записи), флоу полного удаления данных на `Screen.AppData` (сброс счётчиков), `analytics/AnalyticsEvent.kt` (новое событие), `di/AppModule.kt` (фабрика review-флоу), `ui/screens/events/MainScreen.kt` / `ui/viewmodel/MainScreenViewModel.kt` (показ pending на Events-экране). Кнопка «Оценить приложение» (`MoreScreen.kt`, `MoreScreenViewModel.kt`) не меняется.
- **Зависимости**: новая внешняя зависимость `ru.rustore.sdk:review:10.5.2` (только rustore flavor), новый maven-репозиторий.
- **Тесты**: новые unit-тесты (доменная milestone-логика, контракт лаунчера, хранилище счётчиков) и flavor unit-тесты SDK-лаунчера (`app/src/testRustore/`); SDK-флоу на эмуляторе невоспроизводим — SDK-ветка проверяется вручную на устройстве с RuStore.
- **Ограничение SDK**: лимит отображений регулируется на стороне RuStore, частые вызовы не гарантируют показ формы; кнопка SDK не вызывает, поэтому рекомендация доков «не использовать кнопку как триггер» выполняется сама собой, а ошибки авто-запросов обрабатываются тихо.
