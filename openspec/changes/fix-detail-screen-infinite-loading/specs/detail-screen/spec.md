# Spec Delta

## Purpose

Поведение экрана деталей при загрузке записи по идентификатору: успешное отображение данных события и реакция на отсутствие записи в базе — сообщение об ошибке вместо бесконечной загрузки, включая стабильность состояния при повторных эмиссиях потока и после удаления записи пользователем.

## ADDED Requirements

### Requirement: Открытие экрана с несуществующим id показывает ошибку вместо вечной загрузки

При открытии экрана деталей с идентификатором, для которого поток записи не содержит значения (запись отсутствует), система MUST отобразить состояние ошибки с локализованным сообщением (строка `event_not_found`: «Событие не найдено» / «Event not found») вместо бесконечного состояния загрузки.

#### Scenario: Экран открыт с id отсутствующей записи

- **WHEN** экран деталей открыт с id, которого нет в базе (восстановление back stack после смерти процесса, битый deep link/шорткат с устаревшим id)
- **THEN** отображается состояние ошибки с текстом из строки `event_not_found`; бесконечный индикатор загрузки не остаётся

---

### Requirement: Стрелка назад доступна во всех состояниях экрана

Кнопка навигации «назад» в TopAppBar экрана деталей MUST отображаться и MUST работать в состояниях загрузки и ошибки.

#### Scenario: Возврат назад из состояния загрузки

- **WHEN** экран деталей находится в состоянии загрузки
- **THEN** кнопка «назад» в TopAppBar отображается и возвращает пользователя на предыдущий экран

#### Scenario: Возврат назад из состояния ошибки

- **WHEN** экран деталей находится в состоянии ошибки
- **THEN** кнопка «назад» в TopAppBar отображается и возвращает пользователя на предыдущий экран

---

### Requirement: Повторные эмиссии отсутствия записи не меняют установленное состояние

Повторные эмиссии отсутствия записи (Room ре-эммитит поток при изменениях таблицы) MUST NOT менять уже установленное состояние экрана — реакция на «записи нет» идемпотентна.

#### Scenario: Повторная null-эмиссия при активной ошибке

- **WHEN** экран уже находится в состоянии ошибки и поток записи снова эммитит отсутствие записи
- **THEN** состояние экрана не меняется: сообщение об ошибке остаётся без мельканий и перезагрузок

#### Scenario: Null-эмиссия после собственного удаления записи не меняет состояние

- **WHEN** пользователь удаляет запись с экрана (экран сразу закрывается) и поток записи после удаления эммитит отсутствие записи
- **THEN** состояние закрывающегося экрана не переводится в ошибку; успешное состояние сохраняется до закрытия
