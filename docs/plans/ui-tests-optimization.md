## Не делаем (осознанно)

- **SubscriptionTimeout.kt + правило в androidTest** — ни один androidTest
  не пережидает 5+ с. Вернуться, только если появятся LiveUpdate-подобные
  тесты с фикс-снами на таймаут подписки.
- **Шардирование на 2 AVD** (≈ ×1.8) — полный прогон короткий, второй
  AVD (2–3 GB RAM) не окупится.
- Параллельный executor внутри одного AVD — гонки ломают детерминизм Compose-тестов.
- `org.gradle.workers.max` вручную — не наш рычаг для androidTest.
- Удаление/группировка тестов — потеря покрытия запрещена.
- Менять `waitUntil`-таймауты — обоснование в Контексте.
- Настройки анимаций внутри тела `android-test` — неявная мутация
  глобального состояния; для этого отдельная цель `emulator-fast`.

## Находка

AGP 9 в этом репо пишет `time="0.000"` во все элементы XML — device-сумма
бесполезна для A/B. На решение не повлияло (хватает wall); если когда-то
понадобится — парсить gradle logs (`--info`).
